CARDBOARDED - MULTIPLAYER NOTES
===============================
How online play is built, why it's built that way, and where to change things.
Updated every time multiplayer is worked on. History of changes: MULTIPLAYER_CHANGELOG.txt

Networking library: FishNet (Assets/FishNet)
Transport: Unity Transport through Unity Relay, with lobby codes.
  - Adapter: "FishyUnityTransport" package (component is called UnityTransport,
    namespace FishNet.Transporting.UTP), from
    https://github.com/ooonush/FishyUnityTransport
  - Unity packages: com.unity.transport, com.unity.services.multiplayer
    (contains Relay + Authentication)
  - Unity Cloud project "Card game" is linked (Project Settings > Services),
    Relay is enabled on cloud.unity.com. Environment: production.
  - Works over the internet with no port forwarding, needs an internet
    connection.


-------------------------------------------------------------------------------
1. THE BIG PICTURE
-------------------------------------------------------------------------------

Two players: one HOSTS (their game is the server AND a client at the same time),
the other JOINS by typing the host's lobby code (6 letters/numbers, e.g. K7Q2XB).

Model for the match itself - the "command model" (details in 3c):
  - Clients never change the game directly. They send intents ("play card 7 in
    lane 2") to the server.
  - The server checks them, numbers them and sends them to BOTH clients.
  - Both clients run the same existing game code with the same inputs and the
    same random seed, so both reach the same result and play their own
    animations.
  - Nothing like HP or unit power is sent over the network, only player
    decisions + one random seed at the start.

Done so far: main menu -> lobby -> both players land in the same Board match
with the same seed, the opponent's nickname and a random starting player
(section 3b). Commands work: Ready, workshop results, play card, targets
(3c).


-------------------------------------------------------------------------------
2. FISHNET IN 2 MINUTES (concepts used in this project)
-------------------------------------------------------------------------------

NetworkManager
  The object that runs networking. Lives in the Lobby scene, then carries
  itself over to the next scenes (DontDestroyOnLoad). It's an instance of
  FishNet's demo prefab (Assets/FishNet/Demos/Prefabs/NetworkManager.prefab)
  with our ConnectionScript added on top.

Server / Client / Host
  Server = the authority, holds the "real" values.
  Client = a player's game connected to the server.
  Host   = server + client in one game (what "Host Match" does).

NetworkObject + NetworkBehaviour
  A GameObject with a NetworkObject component exists on the server and on every
  client at the same time ("spawned"). Scripts on it inherit NetworkBehaviour
  instead of MonoBehaviour, which gives them SyncVars and RPCs.
  Useful callbacks (in order): OnStartNetwork, OnStartServer, OnStartClient ...
  OnStopClient, OnStopServer, OnStopNetwork.

Owner
  Each NetworkObject has an owner connection. IsOwner is true on the machine
  that owns it. Your own LobbyClient = the one where IsOwner is true.

SyncVar
  A value the server sets and FishNet copies to every client automatically.
      public readonly SyncVar<bool> ready = new SyncVar<bool>();
      ready.Value = true;          // only works on the server
      ready.OnChange += MyMethod;  // runs on clients when it changes
  OnChange gives (previous, next, asServer). On the host it fires twice (once
  as server, once as client) - we skip the asServer one for UI refreshes.

ServerRpc  (client -> server)
  A method marked [ServerRpc] is called on a client but RUNS ON THE SERVER.
  This is how a client asks for a change: SetReady(true) runs on the server,
  which then sets the SyncVar. By default only the owner of the object can call
  it (RequireOwnership = true), so players can't change each other's values.

ObserversRpc  (server -> all clients)
  A method marked [ObserversRpc] is called on the server and runs on every
  client. Used for one-off events ("the match is starting").

PlayerSpawner
  Component on the NetworkManager. Spawns one copy of a prefab for every player
  that connects (ours: Assets/Prefabs/Lobby/LobbyClient.prefab).

Transport
  The part of FishNet that actually sends bytes. FishNet doesn't care which one
  is used, so swapping transports (Tugboat -> Unity Transport) didn't change
  any lobby/game code. Only ConnectionScript knows about it.

Scene loading
  Network scene changes go through FishNet's SceneManager, not Unity's:
      InstanceFinder.SceneManager.LoadGlobalScenes(new SceneLoadData("Board")
          { ReplaceScenes = ReplaceOption.All });
  "Global" = everyone connected loads it. Only the server can call this.
  Normal SceneManager.LoadScene is still used for offline scene changes
  (main menu <-> lobby).


-------------------------------------------------------------------------------
2b. UNITY RELAY + LOBBY CODES - HOW IT WORKS
-------------------------------------------------------------------------------

Why a relay: home routers block incoming connections, so a guest normally
can't reach the host's computer (that's why IP joining needed port
forwarding). With Relay, BOTH players connect out to a Unity relay server,
which passes messages between them.

Where the code comes from: Relay itself makes it. All of this is in
ConnectionScript:

  Sign in (SignInAsync)
    Relay only talks to signed-in players. We sign in ANONYMOUSLY, players
    never see it. Each launch uses a random profile name, so two copies of
    the game on one PC (Multiplayer Play Mode, two builds) count as different
    players.
      UnityServices.InitializeAsync(options)
      AuthenticationService.Instance.SignInAnonymouslyAsync()

  Host (HostAsync)
    1. RelayService.Instance.CreateAllocationAsync(1)
         reserves a spot on a relay server for 1 guest
    2. RelayService.Instance.GetJoinCodeAsync(allocation.AllocationId)
         gets the short code pointing at that reservation
    3. unityTransport.SetRelayServerData(allocation.ToRelayServerData("dtls"))
         tells the transport to go through that relay ("dtls" = encrypted)
    4. start server + client like before. The host's own client talks to the
       server locally, only the guest goes through the relay.

  Join (JoinAsync)
    1. RelayService.Instance.JoinAllocationAsync(code)  -> finds the host's spot
    2. unityTransport.SetRelayServerData(joinAllocation.ToRelayServerData("dtls"))
    3. start client.

async / await
  Talking to Unity's servers takes a moment. "async" methods let the game keep
  running while waiting; "await" continues the method once the answer comes.
  Failures come back as exceptions, so LobbyManager.ConnectButton wraps the
  calls in try/catch and shows ConnectionScript.GetErrorMessage(...).
  After an await the scene might be gone (player pressed back), so the code
  checks "if (this == null) return;".

Codes
  Typed codes are cleaned up by ConnectionScript.NormalizeCode (no spaces,
  capitals). The code field only accepts letters/numbers and capitalises
  them. A code stops working once the host leaves.


-------------------------------------------------------------------------------
2c. SHARED RANDOMNESS (GameRandom)
-------------------------------------------------------------------------------

Both games must make the same random choices. UnityEngine.Random can't
guarantee that: visual effects also use it, and how often they run depends on
frame timing. So:
  GameRandom          - changes the game AND runs on both machines
  UnityEngine.Random  - visuals, or code only one machine runs (local
                        Workshop, AI). Online, Workshop results are sent
                        as commands.

GameRandom (Assets/Scripts/Core/GameRandom.cs) wraps System.Random.
  Init(seed)   same seed = same numbers. Called in GameManager.Awake with a
               new seed; online it will get the host's seed.
  Range(a, b)  int, b excluded.   Value()  float 0..1.   NewSeed()
  Seed / CallCount  same seed but different CallCount = something rolled on
                    only one machine.

Uses it: D6 final roll, random lane (Field), random discard
(DiscardManager.AutoDiscard), PlayerUI.AddRandomFoodToken, tie-breaks in
KnockOutHighestEachSide, KnockOutLowestEnemy, SetLowestAllyPower,
SwapHighestLowestPower, PushOpposingEnemy.


-------------------------------------------------------------------------------
3. THE LOBBY - HOW IT WORKS
-------------------------------------------------------------------------------

Flow
  Main Menu, play mode screen
    Nickname field at the top (TitleScreen.nicknameField). Saved as it's typed
    into GameData.nickname + PlayerPrefs "nickname". Used for bot matches too.
    "Host Match" -> TitleScreen.CreateOnlineMatchButton -> loads "Lobby" scene.
    "Join Lobby" -> TitleScreen.JoinOnlineLobbyButton -> the button is swapped
    for a small row: code field + Join button + cross to cancel (Enter also
    joins). Join -> GameData.joinCode = typed code -> loads "Lobby" scene.
    If joining fails the lobby sends the player back here: the row opens again
    with the code still in it and the error above it (GameData.menuMessage).

  Lobby scene, CONNECTING
    Nothing to type. LobbyManager.Start -> ConnectNextFrame -> Connect():
      host  -> HostAsync
      guest -> JoinAsync(GameData.joinCode)
    A loading screen covers this. Our LobbyClient spawns -> lobby screen.
    Host error  -> CONNECT SCREEN with the error + "Open lobby" retry button.
    Guest error -> back to the main menu code row with the message
                   (LobbyManager.ReturnToMainMenu(message)).
    Back arrow -> main menu.

  Lobby scene, LOBBY SCREEN (appears once your own LobbyClient is spawned)
    Two player cards: left = host (seat 0), right = guest (seat 1).
    Empty seat shows "Waiting for player..." with a spinner.
    Ready button switches between ready / not ready. Faded and not clickable
    until the other player has joined (the server also refuses SetReady(true)
    with only one player).
    Start button: host only, clickable only when both players are ready.
    Back arrow = leave -> main menu. If the host leaves, the lobby closes and
    the guest is sent to the main menu with "The host closed the lobby".
    Host sees the lobby code on a sticky note, with a Copy button (puts it on
    the clipboard, ready to paste into Discord).

  Start pressed
    host client --RequestStartMatch (ServerRpc)--> server
    server re-checks both players are in and ready, stops accepting players,
    sends MatchStartingRpc (ObserversRpc) to everyone
    every client saves seat + nicknames into GameData, resets PlayerConfig
    server waits matchStartDelay (1.2s), then loads Board for everyone.

Files
  Assets/Scripts/Lobby/ConnectionScript.cs  (on the NetworkManager)
    - HostAsync() -> returns the lobby code, JoinAsync(code), Leave(),
      Shutdown(). joinCode = code of the lobby we host.
    - SignInAsync, NormalizeCode, GetErrorMessage (see 2b)
    - Turns away a 3rd player and anyone joining after the match started
      (OnRemoteConnectionState -> conn.Disconnect)
    - Events for the UI: OnLocalConnectionStarted, OnLocalConnectionStopped
    - maxPlayers = 2

  Assets/Scripts/Lobby/LobbyClient.cs       (on LobbyClient.prefab)
    - One per connected player. Networked.
    - SyncVars: nickname, ready, seat (0 host, 1 guest)
    - Server assigns the seat in OnStartServer (host's own connection = 0,
      otherwise first free seat)
    - ServerRpcs: SetNickname, SetReady, RequestStartMatch
    - ObserversRpc: MatchStartingRpc
    - LobbyClient.all = every LobbyClient on this machine,
      GetLocal() = yours, GetBySeat(i)
    - When a player leaves, the server un-readies the remaining player.

  Assets/Scripts/Lobby/LobbyManager.cs      (Lobby scene, Managers)
    - Plain MonoBehaviour, NOT networked. Draws the UI from LobbyClient values.
    - Refresh() is called whenever a SyncVar changes or a player joins/leaves.
    - Server side: TryStartMatchServer() + loading the Board scene.
    - Error messages before connecting (ConnectionScript.GetErrorMessage):
        "No lobby with that code"                    - Relay doesn't know the code
        "Couldn't reach the online service..."       - no internet / Unity down
        "Too many tries, wait a moment..."           - Relay rate limit
    - Error messages after a disconnect (OnLocalConnectionStopped):
        "The host closed the lobby"            - we were in, connection dropped
        "Couldn't join, the lobby is full..."  - connected, got kicked at once
        "Couldn't connect to the lobby..."     - Relay found it, connecting failed

  Assets/Scripts/Lobby/LobbyPanel.cs        (each player card)
    - Show(client, isLocal): nickname/status/"You" tag, empty seat look,
      pop animation when a player joins or gets ready.

  Assets/Scripts/Core/GameData.cs
    - nickname, nicknamePrefKey, maxNicknameLength (16)
    - GetDisplayNickname(): nickname -> saved nickname -> "Player"
    - hostingLobby, joinCode, menuMessage (main menu <-> lobby)
    - localSeat, seatNicknames (read in the Board)

  Assets/Scripts/MainMenu/TitleScreen.cs
    - Nickname field (loads/saves PlayerPrefs)
    - Join code row: JoinOnlineLobbyButton, OpenJoinCodeRow, CloseJoinCodeRow,
      JoinWithCodeButton. On Start, if GameData.menuMessage is set, jumps
      straight to the play mode screen with the row open and the message.
    - Lobby buttons; Start() shuts down a leftover NetworkManager when you come
      back to the menu after an online match.

Lifetime of the NetworkManager
  Created with the Lobby scene. Survives into Board. Destroyed by
  ConnectionScript.Shutdown() when going back to the main menu (lobby back
  arrow, or TitleScreen.Start). That way entering the lobby again always gives a
  fresh one and there are never two.


-------------------------------------------------------------------------------
3b. THE MATCH START (Board)
-------------------------------------------------------------------------------

Flow
  LobbyManager.OnMatchStarting sets PlayerConfigObj.offlineMatch = false.
  (GameManager.Awake sets it back to true when no client connection is
  running, so pressing Play in the Board scene is always a bot match.
  GameManager runs at execution order -100, before Player/AIOpponent.)
  Board loads. Each player's fog shows "Waiting for opponent...".
  Each client: MatchNetwork.OnStartClient -> ClientLoaded (ServerRpc)
  Server: once both clients have loaded, picks a seed (GameRandom.NewSeed)
    and a random starting seat, sends StartMatchRpc (ObserversRpc).
  Each client: GameManager.StartOnlineMatch(seed, firstSeat)
    -> GameRandom.Init(seed), firstPlayer = player or opponent, fog lifts.

Sides
  Each machine sees itself as GameManager.player and the other seat as
  GameManager.opponent. Seat -> side: firstSeat == GameData.localSeat means
  "player goes first". Opponent nickname = GameData.seatNicknames[1 - localSeat].

Turns
  GameManager.firstPlayer starts every placing phase (offline: always the
  player). Workshop/battle start with the local player as before.
  Online opponent: Player.isRemote = true (isAI is false, AIOpponent removes
  itself). Player.StartTurn on a remote player calls
  GameManager.StartRemoteTurn: "opponent's turn", waitingForRemote = true,
  the game waits for their command. Player.EndTurn on a remote player calls
  GameManager.EndRemoteTurn (works like AIOpponent.AIEndTurn).

Files
  Assets/Scripts/Network/MatchNetwork.cs  (scene object "MatchNetwork" in
    Board, has a NetworkObject). Does nothing in bot matches, since no
    network is running there.
  Assets/Scripts/Core/GameManager.cs  StartOnlineMatch, StartRemoteTurn,
    firstPlayer, waits in StartGame until the match starts.
  Assets/Scripts/Core/Player.cs  isRemote, opponent nickname in InitPlayer.


-------------------------------------------------------------------------------
3c. COMMANDS (MatchNetwork)
-------------------------------------------------------------------------------

Flow
  Local decision (e.g. ReadyButton.ButtonClick, online)
    -> MatchNetwork.SendReady() -> CommandServer (ServerRpc)
  Server: sets the sender's seat (remembered from ClientLoaded), gives the
    next number, sends CommandRpc (ObserversRpc) to both.
  Each client: puts it in commandQueue. MatchNetwork.Update applies them in
    order, once CanApply says the game is at the right point.
  The sender doesn't apply its own move before it comes back, so both games
  apply everything in the same order through the same code.

MatchCommand (struct, FishNet sends it as is)
  number   order from the server. Clients log an error if one is skipped.
  seat     who made it (set by the server, not trusted from the client).
  stateNr  GameManager.stateNr when it was made (+1 on every state change).
  type     CommandType enum. Add new commands here.
  index, cardName, abilityName, color, abilityColor, layer1, layer2
           values, which ones are used depends on the type (see the struct).
           Unused ones stay empty and cost almost nothing.

CanApply (when a command waits in the queue)
  - stateNr is ahead of ours: the other player got to the next state first
    (skipped animations), wait until we're there.
  - ChooseTarget: only while this game is asking for a target
    (ExecuteManager.targetOptions != null), whoever sent it.
  - own commands: apply right away.
  - other player's StopDice: once their dice are rolling here.
  - other player's: only in the workshop (both act at once) or while
    waitingForRemote (their turn here too). Apply clears waitingForRemote,
    so nothing else of theirs runs while their move is still animating.

Ready (CommandType.Ready)
  GameManager.PlayerReady(p): endStateReady = true, then EndTurn (local) or
  EndRemoteTurn (remote). Offline the ReadyButton calls PlayerReady directly.
  Placing with an empty hand: GameManager.StartTurn auto-sends Ready online
  (offline it also readies an opponent with an empty hand, online each game
  does that for its own player).

Play card (CommandType.PlayCard: index = card in hand, lane = Player.fields)
  Field.PlayCard checks the rules (mouse over the field, free slot,
  CanPlayCard). Online it then only sends the command: sets
  player.cardPlayed (no second drag while waiting), hides Ready, returns
  true. The card is hidden (SetActive false) until the command returns,
  PlayCardNow shows it again.
  Field.PlayCardNow does the actual play (must play special, random lane
  with GameRandom, spawn, ability). Offline and bot cards go straight there;
  online MatchNetwork.ApplyPlayCard calls it on both games.
  The play ends in ExecuteManager -> card.player.EndTurn(), which for the
  remote player goes to GameManager.EndRemoteTurn.

Dice (CommandType.StopDice: index = how many dice)
  Rolling dice wait in D6.rollingDice (oldest first). The bot's stop by
  themselves. A click stops all of the local player's rolling dice
  (D6.StopDice) and online sends StopDice with the count. The other game
  keeps the remote player's dice rolling until the command comes (CanApply
  waits until that many of their dice are rolling there), then stops the
  oldest ones. Value comes from GameRandom when a die stops, so both games
  get the same numbers.

Targets (CommandType.ChooseTarget: index = unit in targetOptions)
  EffectContext.ChooseTarget -> ExecuteManager.ShowTargets(options, hint,
  Owner). The effect's owner chooses (targetChooser): bot picks at random,
  local player clicks (Unit.TargetOnClick, allowed while
  ExecuteManager.LocalPlayerChooses), remote player's pick arrives as a
  command. Online the click goes through ExecuteManager.PickTarget -> sends
  the index, both games set effectTarget when it comes back.
  Index works because the options list is built from FieldManager.unitList
  in the same order on both games.

Discard after battle (no command, it's random)
  BattleManager end: online both picks are rolled up front with
  DiscardManager.RollAutoDiscard, in seat order (host first), so both games
  use GameRandom the same way. Own pick goes into
  StartDiscardSequence(player, true, pick) -> AutoDiscard shows it, the
  opponent's card is destroyed directly (like the bot's). Offline the pick
  is still rolled at the end of the animation.

Desync check (MatchNetwork.CheckSync)
  At every state change (GameManager.TransitionGameState, before the new
  state does anything) both games should be identical. Each sends a text
  snapshot (GetSnapshot) to the server: state, round, GameRandom.CallCount,
  and per seat (seat 0 first): hp, stars, random lane / must play special,
  hand + knocked out card names, every lane's blocked count + units + power.
  Server keeps the first one per stateNr and compares with the second.
  Different -> DesyncRpc -> red error on both games with both snapshots.
  Not after every command: commands land at different moments on the two
  games (animations), only state changes are a common point.
  Finding the cause: compare the two snapshots, then look for gameplay
  code that ran on one game only or used UnityEngine.Random.

Disconnects (GameManager.OnOpponentLeft)
  How each side finds out:
    host   ConnectionScript.OnRemotePlayerLeft (server saw the guest's
           connection stop; turned away joiners are ignored via turnedAway)
    guest  ConnectionScript.OnLocalConnectionStopped (host left, or this
           player's own connection dropped - can't tell which)
  What happens:
    before the match started (fog) -> "<name> left the match" on the fog,
      main menu after opponentLeftMenuDelay (2s)
    during the match -> game over screen with that text (ManagerUI.
      GameOverScreen customText), nothing else gets processed
    after a normal game over -> the host's Restart button is hidden
  Leaving yourself (settings exit, game over menu button) loads the main
  menu, TitleScreen.Start shuts the network down, the other side gets the
  event above.

Restart (ManagerUI.Rematch)
  Online only the host sees the Restart button (ManagerUI.GameOverScreen ->
  EnableRematch), and only while the opponent is still there.
  Click -> ConnectionScript.RestartMatch: the server loads the empty
  "Rematch" scene for everyone, then Board again (FishNet can't reload a
  scene that's already open on clients). The new Board starts like the first
  one: MatchNetwork waits for both, new seed and new starting seat.
  Offline it just reloads Board.

Workshop results (PickColor, CreateCard, DiscardFromHand)
  Exception to "nothing before it comes back": the workshop only changes
  your own hand and both players work at the same time, so the sender's game
  applies it right away (existing workshop code) and sends the command.
  MatchNetwork.Apply only runs these for the remote player.
  Order still holds: they're sent before your Ready, so the other game gets
  your cards before it hears you're done.
  - PickColor: WorkshopColorSelect.LockPencilChoice. Other game sets the
    opponent's playerColor (+ PowerCounter.RefreshColor).
  - CreateCard: Workshop.CreateNewCard, sent before CardGenerator.CreateCard.
      ability  sent by asset name -> CardGenerator.GetAbilityByName
      art      drawing: both layers as PNG bytes (256x256, a few KB;
               FishNet splits big reliable messages itself)
               empty canvas: index of the preset in
               CardDatabase.GetAllPresets() (sets in order, basic then special)
      colors   second color + ability color as they are.
    Other game builds the same CreatureObj and calls CreateCard for the
    opponent (hand full check is the same on both).
  - DiscardFromHand: DiscardManager.DiscardUnitSequence (only the workshop
    "destroy for a coin", not the random discard after battle). Sends the
    card's index in cardsInHand, other game calls DestroyCard on it (counts
    as a dead unit there too).
  Hand order matters: indexes only work because both games add/remove the
  same cards in the same order.
  Not sent: shop stars (the opponent's stars don't affect this game).

Adding a command (example: play card)
  1. Add to CommandType, add fields to MatchCommand if it needs values.
  2. MatchNetwork: public SendX(...) that fills a MatchCommand + SendCommand.
  3. MatchNetwork.Apply: case CommandType.X -> call the existing game code
     for the right Player (p).
  4. Online, the UI calls SendX instead of the game code.

4. WHERE TO CHANGE THINGS
-------------------------------------------------------------------------------

  Lobby texts (hints, errors)     LobbyManager.Refresh / OnLocalConnectionStopped
  Max nickname length             GameData.maxNicknameLength
  When Ready is allowed           LobbyManager.Refresh (button) +
                                    LobbyClient.SetReady (server check)
  Default nickname ("Player 1")   LobbyClient.DefaultNickname
  Who may press start             LobbyClient.RequestStartMatch (seat check)
  Start conditions                LobbyManager.TryStartMatchServer
  Delay before Board loads        LobbyManager.matchStartDelay (inspector)
  Which scene the match uses      LobbyManager.LoadBoardAfterDelay ("Board")
  Max players / kicking           ConnectionScript.maxPlayers, OnRemoteConnectionState
  Relay connection type           ConnectionScript.relayConnectionType ("dtls")
  Error texts for codes           ConnectionScript.GetErrorMessage
  Code note / copy button         LobbyManager.Refresh, CopyCodeButton
  Transport settings              UnityTransport component on the NetworkManager
  Gameplay random numbers         GameRandom (seeded in GameManager.Awake,
                                    online in StartOnlineMatch)
  Who starts placing              MatchNetwork.ClientLoaded (firstSeat)
  New command types               CommandType / MatchNetwork.Apply (see 3c)
  When a command may run          MatchNetwork.CanApply
  Online restart                  ConnectionScript.RestartMatch (+ "Rematch" scene)

Adding a new synced lobby value (example: chosen color)
  1. LobbyClient: public readonly SyncVar<int> color = new SyncVar<int>();
  2. Subscribe it in OnStartNetwork / unsubscribe in OnStopNetwork
     (color.OnChange += OnValueChanged;) so the UI refreshes.
  3. Add a [ServerRpc] SetColor(int value) { color.Value = value; }
  4. Call LobbyClient.GetLocal().SetColor(x) from the UI.
  5. Show it in LobbyPanel.Show.
  6. If the board needs it, copy it into GameData in LobbyManager.OnMatchStarting.

5. TESTING
-------------------------------------------------------------------------------

Needs an internet connection (Relay is online even when testing on one PC).

Two players on one computer: Multiplayer Play Mode (already in the project)
  Window > Multiplayer > Multiplayer Play Mode, tick Player 2. Open the Main
  Menu scene and press Play. In one window press Host Match, press Copy on
  the code note, in the other Join Lobby -> paste the code -> Join.

Don't pause the editor while in a lobby for long: Relay drops players that
go quiet ("player timed out due to inactivity"). With "Error Pause" turned on
in the Console, that error pauses the editor again and again.

Two computers anywhere: host sends the code (Copy -> paste in Discord), the
other player types it in. No port forwarding needed.


-------------------------------------------------------------------------------
6. KNOWN LIMITS / TODO
-------------------------------------------------------------------------------

  - All player decisions of a round are synced, desync check and
    disconnects are in. No reconnecting: a dropped player can't come back.
  - A desync is only reported, the match keeps going.
  - Both players can pick the same color.
  - Between pressing Ready and the command coming back, the player can
    still act (short window, button is disabled).
  - LobbyClient objects are destroyed when Board loads. Seat and nicknames
    survive in GameData.
  - If a player disconnects during the 1.2s before Board loads, Board still
    loads for whoever is left. The leave happened before the Board existed,
    so the host can still end up waiting in the fog (rare).
  - No LAN/offline fallback: without internet you can't host. (FishNet's
    Multipass could run Tugboat next to Unity Transport if this is ever needed.)
  - Relay free tier has usage limits, check the Unity dashboard if the game
    gets lots of players.
  - FishyUnityTransport was last updated April 2025 (made for FishNet 4.5);
    works with our FishNet 4.6.12 as tested. If a FishNet update breaks it,
    look there first.
